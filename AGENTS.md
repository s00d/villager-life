# AGENTS.md — Villager Life (NeoForge 1.21.1 … 26.3)

Отвечай пользователю **по-русски**. Этот файл — вход для агента: что за проект, как собирать, как проверять, чего не делать и что сейчас не доделано.

## Что это

- Мод **Villager Life**, автор s00d, лицензия своя, source-available: читать и изучать можно, копировать, менять и распространять нельзя (`LICENSE`, 24.10.2026; до того MIT, там же — какие ассеты сгенерированы). Публичный репозиторий — `s00d/villager-life` (с 24.10.2026, без истории: одно стартовое состояние 1.0.0); прежний приватный `s00d/villager-news-addon-neoforge-port` с историей остался как есть. Голоса-референсы `tools/voice/speaker/**/ref.wav` в git не идут (`.gitignore`). Чистая комната 21.10.2026: код, модели, звуки и персонажи прежнего аддона заменены своими (тексты реплик — отдельная работа).
- Ветка `main` (по умолчанию на GitHub; до 19.10.2026 работа шла в `neoforge-1.21.1`, она осталась как есть). Stonecutter 0.9.8, узлы `neoforge/versions/<v>`: **1.21.1** (исходники написаны для неё, dev-клиент, NeoForge 21.1.252, Java 21), 1.21.4, 1.21.8, 1.21.11, 26.1.2, 26.2, 26.3 (26.x — Java 25). Пропущены: 1.21.2/1.21.3 (1.21.4 вышла через недели, JEI нет), 1.21.5 (мало паков, середина переписи GameTest/NBT), 1.21.6/1.21.7/1.21.9/1.21.10 (закрыты 1.21.8 и 1.21.11), 26.1/26.1.1 (26.1.2 с диапазоном `[26.1,26.2)`). Как вести код для всех версий — «Версии Minecraft» ниже.
- `mod_id` = `villager_life`, `mod_version` = `1.0.0` (jar на каждый язык озвучки: `villager-life-1.0.0+<mc>-<lang>.jar`, см. «Сборка»).
- Namespace ассетов и реестров = **`villager_life`** (= mod_id; до 21.10.2026 был `villager-news-addon-port`, старые миры с ним не грузят блоки мода — не поддерживаем). Java-пакет `com.vnap`.
- Поверх оригинала: двуязычная озвучка EN/RU (локальный TTS), настроение деревни и обряды, жители строят руками, профессии как «жизнь», свои дома, 26 декор-блоков с механиками и 12 станков с GUI, JEI/EMI, справочник.

## Инструменты агента

Справочник — **`tools/dev/README.md`** (читать перед живой проверкой), навык `.claude/skills/vl-dev` (Claude Code находит его сам). Новый инструмент — в README, навык и сюда.

Скриншоты для страниц мода (24.10.2026): `F1`, окно скрыто (`mc.client.window`), `/vnapcam fov 70` (интерьеры 100), камера — наблюдателем `/tp x y z yaw pitch`, сцена замораживается `/tick freeze`. Код один: исходники пишутся на API NeoForge, на Forge-узлах `net.neoforged.` переименовывается в `com.vnap.neo.` — **шим** `neoforge/src/main/java/com/vnap/neo/**` (на NeoForge-узлах исключён), он повторяет нужную часть API NeoForge 1.21.1 поверх Forge. Константы Stonecutter `forge`/`neoforge`: `//? if >=1.21.6 && forge`. Jar — `villager-life-forge-1.0.0+<mc>-<lang>.jar`.
- **События** — `com.vnap.neo.Bridge`: класс события шима при загрузке привязывается к событию Forge (`Bridge.bind` → `Bridge.game/mod`), первая подписка на приоритет вешает одного слушателя Forge, отмена идёт обратно. EventBus 6 (до 1.21.5: `MinecraftForge.EVENT_BUS`, шина мода) и EventBus 7 (с 1.21.6: `BUS` у каждого класса, шина мода — `getBus(BusGroup)`; с 26.1 события мода тоже глобальные — берётся `BUS`). Событие без своей шины едет по шине родителя вместе с братьями (`CriticalHitEvent` по `PlayerEvent.BUS`) — `Bridge` фильтрует по типу. Своих событий у Forge нет — `Bridge.own` + `Bridge.fire` из миксинов `com.vnap.neo.mixin` (`villager_life.forge.mixins.json`): HUD (`GuiRenderMixin`, слои — `ForgeLayeredDrawMixin`), урон, тик сущности, заточка, музыка, табличка имени, смена атрибутов предмета.
- Вход — `com.vnap.neo.ForgeEntry` (`@Mod` Forge): строит `VillagerLife` и клиент, подписывает классы `@EventBusSubscriber` по скан-данным.
- Что сделано иначе, чем у NeoForge: тикеты чанков (`TicketController`) — до 1.21.4 `ForgeChunkManager`, с 1.21.5 свои ванильные `TicketType` `villager_life:forced`/`loaded` (не сохраняются: город и Шпиль берут их заново); модели «сами по себе» (`McClient.registerModel`) — с 1.21.2 через state definition на модель (`com.vnap.neo.client.Standalone`, blockstates `vnap_standalone/*` пишет сборка); synced-флаги жителя с 1.21.6 — entity data, а не вложения (Forge их не запрещает); NBT целиком (`Mc.put/tagOf`) с 1.21.6 — одним значением `VillagerLife` (у Forge нет `store(CompoundTag)`/`keySet()`); сохранённые данные с 1.21.11 — ванильный `SavedDataType` с реестрами запущенного сервера; на 26.x переименования NeoForge (`BreakBlockEvent`, `getHealthDamage`, `TagsUpdatedEvent.ServerDataLoad`) не применяются — шим держит имена 1.21.1; сделки (26.1+) и варка (26.3+) — данные, их шим-события исключены.
- **GameTests на Forge** с 1.21.5: Forge их не регистрирует (`gameTestServer` — ванильный `net.minecraft.gametest.Main`), шим `RegisterGameTestsEvent` пишет окружения и тесты встроенным датапаком (временная папка, `AddPackFindersEvent`, pack.mcmeta мода). До 1.21.4 — аннотации Forge (`GameTestHolder`/`PrefixGameTestTemplate` переписываются), `fixGameTestBlockPosAsserts=false` в `forge-common.toml` прогона. Запуск: `VL_MC=1.21.8-forge tools/dev/gts.sh` (один сервер) или `./gradlew … :neoforge:<v>-forge:runGameTestServer`. 26.10.2026: 369/369 на всех семи Forge-узлах.
- Живая проверка: `VL_MC=<v>-forge python3 tools/dev/server.py build|start N` — прод-сервер Forge из установщика (кэш `~/.cache/vl-minecraft/forge-server/<mc>-<forge>`), jar мода и MCP-мод `minecraft_mcp-forge-0.6.0+<mc>.jar`; клиент — `python3 tools/dev/prod_client.py start <v>-forge` (portablemc `forge::<mc>-<forge>`; JEI для Forge есть только у 1.21.1, без него клиент идёт без окна рецептов), сцены — `VL_SERVER_N=9 python3 tools/dev/client_check.py <v>-forge` (номер сервера — `VL_SERVER_N`, по умолчанию 8). 26.10.2026: все семь версий — 8/8 сцен. Клиентские миксины шима проверяет только живой клиент (GameTests их не грузят): так нашлось, что с 26.2 Forge решает имя над головой в своём `extractNameTags(…, double, double)` (`EntityRendererNameTagMixin.TAGS`).
- Отличия Forge, которые ловили живьём: `EntityJoinLevelEvent` Forge зовёт, когда чанк новой деревни ещё не готов — чтение блоков в нём вешает сервер навсегда (`VillagerMoments.walled`, укладка младенца `Infants` ждут `getChunkNow`); сетевой кодек `ShapedRecipe` Forge падает на пустых клетках — рецепты едут кодеком данных (`com.vnap.neo.network.RecipeContent`, `RecipeLookup`); загрузчик моделей `neoforge:separate_transforms` сборка переписывает в `forge:` (`build-forge.gradle`); установщик Forge отвечает 403 без `User-Agent` (`server.py`).
- **MixinExtras** (26.10.2026): `@WrapMethod`, `@WrapOperation`, `@Local`, `@Share` и т. п. можно брать вместо самописного. NeoForge несёт его сам, Forge — с 1.21.11; на Forge 1.21.1–1.21.8 `build-forge.gradle` кладёт `mixinextras-forge` 0.5.4 в jar мода (jar-in-jar, `META-INF/jarjar`) и в рантайм прогона из классов (дважды на classpath нельзя: пакеты разойдутся по двум модулям). ErrorProne знает его обработчики (`UnusedMethod:ExemptingMethodAnnotations` в `gradle/analyzers.gradle`).
- **Гонка палитры секции** (`mixin/PalettePublishMixin`, все версии и загрузчики): поток света читает блоки чанка, пока сервер их ставит; новая запись палитры (значение, размер, номер в хранилище) — обычные записи без барьера, и на Apple Silicon поток света видел номер раньше размера — `MissingPaletteEntryException`, сервер вис в ожидании чанка. Чаще всего после тестов Шпиля (этаж — 24000 блоков за тик). `valueFor` ждёт публикации и читает снова; настоящая нехватка — исключение, как было.
- Нестабильные тесты 26.10.2026 и их причины (в коде, не в тестах): хозяин занял кровать своим тактом раньше `HomeProjects.finish` — `VillagerHome.claim` теперь сразу выселяет того, кто помнил ту же кровать (`squattersOut`, как `keepHome`); житель постоял на последней клетке изгороди — стройка вставала на сутки после 4 отсрочек (`Hands.STUCK_AFTER` 4 → 20, ≈ минута); колодец считал слитые сферы опыта за одну (`ExperienceOrbAccessor`); первая волна Колизея набирала «контр-оружейных» сверх доли, когда все четыре кандидата такие (`Arena`: добор до 16); стена брала в кольцо чужое — брошенную стройку и могилы другого города (`Roads.owned`/`townsOwn`, `Wall.lastRefusal`, `/vnap roads wall` пишет причину). Общие для потоков генерации карты — `ConcurrentHashMap` (`VillagerTalk.BORN_OF`, `MegaWork.CALM`: их трогает `FinalizeSpawnEvent` из генерации).
- Попутно найдено и исправлено для всех: хранитель Шпиля целился (метки, прыжок, нырок) в того, кто вне зала (`KeeperArts.aim`), и уходил из зала; тесты свитка снимали «принудительную загрузку» с чанков соседних тестов; площадка теста не чистила настроение/обряд прошлого теста в той же клетке (`TestGround.clear`); с 1.21.5 `succeedWhen` зовёт проверку и после успеха (тесты с уборкой в конце держат флаг `done`).

- Если прогон снова стал долгим, ищи один тест, который держит тик: в логе `Can't keep up! … ticks behind`; `jstack <pid сервера>` (процесс с `fml.modFolders`, не gradlew) покажет его. ### Анализаторы (частые падения)

`-Werror` + ErrorProne + NullAway (`@Nullable` из `org.jspecify`) + SpotBugs. Что уже ловили:
- `ReferenceEquality` → `.equals()` / `stack.is(...)`; `OperatorPrecedence` → скобки вокруг `a && b` внутри `||`.
- Generic varargs → перегрузки; массивы в record-компонентах запрещены; enum с изменяемыми полями → record.
- В gametest не использовать устаревший `makeMockServerPlayerInLevel` (ещё и шлёт наш payload мок-соединению) → `helper.makeMockPlayer(GameType.SURVIVAL)`; NullAway в тестах → `instanceof`-паттерны и ранний `fail`.
- Миксины не используют унаследованные `@Shadow`-методы.

### Тайга и саванна: двери и кровати (20.10.2026)

- **Не дошёл до кровати — в укрытие** (24.10.2026, живая проверка: житель ночевал под стеной своего дома и погибал): ночью житель с кроватью, который в отдыхе или панике стоит на месте три семейных такта (`Shelter.stuck`) и с этого места не имеет пути к кровати (`Shelter.reaches`, точность 1, как у ванильной ходьбы домой), идёт в укрытие, как бездомный (лог `vnap stranded`). Причина любая: ставня перед дверью, блок игрока, снесённый дом. В панике он бежит в укрытие, а не к кровати (`RunHome`); `homeward` такого не трогает и переносит к кровати только в клетку её комнаты (раньше переносил за стену). Ночной пакет исполняет свою запись укрытия, где бы она ни стояла в очереди (`Agenda.of`), а «не может дойти» от прошлой цели при старте записи сбрасывается (иначе укрытие бросалось сразу). Житель, у которого ваниль стёрла колокол (долго не мог до него дойти), получает его назад (`Towns.seen`), иначе для мода он был не из города. `/vnap home` пишет `night:` и для жителя с домом.
- **Ставни не преграда** (`WalkNodeEvaluatorMixin.vnap$shutter`): открытый люк, висящий над воздухом панелью к стене, проходим, как в ванили; забором остаётся только люк, стоящий на земле (клумбы тайги). Раньше каждая пара ставен делала вдоль стены тупик. Ставня не вешается на «косяк», который оказался дверью (`Dressing`). Кровать, плита, ковёр (до 0,6 блока) — не стена комнаты (`FamilyHome.walkable`): кровати поперёк открытой стороны навеса делали его «закрытой комнатой». Мэр не ставит кровати бездомным в дом, где у кого-то есть кровать (`Shelter.lived`): мастерская хозяина заполнялась ночлежными кроватями, и он не мог пройти к своей.
- **Двери закрываются** (`village/life/Doors`, `mixin/InteractWithDoorMixin`, поведение в ядре мозга — `VillagerGoalPackagesMixin.getCorePackage`): ванилла закрывает дверь, только пока житель идёт по пути и не дальше 3 блоков от неё. Житель, чей путь кончился сразу за дверью (таёжный домик — 3 клетки, укрытие — клетка у двери), или пробежавший дальше, оставлял её открытой на всю ночь — зомби, шедший за ним, заходил; в свежей тайге 4 из 8 смертей были в доме. Теперь дверь из `DOORS_TO_CLOSE` закрывается, когда житель не идёт через неё (и до 16 блоков), как только в проёме нет никого, кроме монстра. Тест `aVillagerShutsTheDoorItLeftBehind`.
- **Кровати бездомным — мэр** (`Shelter.beds` из `Roads.plan`, раз в день, только при мэре): взрослые жители города без кровати (ни ванильной HOME, ни своей) и без свободной кровати, к которой ещё можно пойти (`HomeProjects.freeBed`), минус уже ждущие кровати (`Placements.pendingBeds`) — столько кроватей казна покупает, а мэр ставит руками (`Placements` на его имя, через день — любой) в закрытые светлые комнаты построек города, где свободного пола хватает (комната ≥ 6 клеток, не у дверей, `FamilyHome.keepsOpen`). `Placements.place` ставит кровать целиком (изголовье с изножьем). Бездомный ночует в ней по-ванильному — это ночлег, не дом (дом покупается, `Housing`). Тест `theMayorSetsABedForEveryHomelessVillager`.
- **Укрытие до утра**: из укрытия выходят в 1000, а не в 23400 (вышедший до рассвета встретил у двери зомби, которого солнце ещё не сожгло). Не нашёл комнату — ищет снова через минуту (`LOOK_AGAIN`), а не раз за ночь. `/vnap home` пишет, почему не подошли комнаты (`small`, `open`, `dark`, `unreached`).
- **Гроза = ночь** (`Shelter.storm`, `mixin/UpdateActivityFromScheduleMixin`): в грозу монстры спавнятся днём на открытом месте (все 118 дневных спавнов на открытом месте у саванны — в одну минуту, в неё же погибли 7 жителей). Житель города в грозу живёт ночью: расписание даёт REST (домой, в кровать; бездомный — в укрытие, `Shelter.night` учитывает грозу), в комнате монстр снаружи не угроза (`VillagerHostilesSensorMixin`). Набат колоколом пробовали — хуже: ванильное «прятаться» ведёт к любой кровати за 30–80 блоков и не убегает от зомби по дороге (7 из 7). Замер: две свежие саванны, 6000 тиков грозы днём — 0 и 2 смерти.
- **Поиск места у стройки** (`Hands.findSpot`): один поиск пути сразу ко всем 24 ближайшим местам (`createPath(Set, 0)`), а не по поиску на каждое: недостижимая клетка была 8 проваленными поисками по всей области, и разборщик (`Wrecker`) или дорожник, идущий по списку таких клеток, тратил 30 мс за тик — 41% времени сервера в таёжном городе (`jstack` во время перемотки). Перемотка того же города 221 → 259 тактов/с; остальное — ванильные мобы и чанки (код мода < 1%).
- **Отладка такта**: `vnap slow: <имя> <мс> at … act= run=[поведения] walk= path= time` — любой тик жителя дольше 20 мс (не чаще раза в 200 тиков на жителя). `/vnapsim [чанки]` (клиент) — дальность симуляции на ходу (не сохраняется; `/vnapsim 12` — вернуть): город держится своими тикетами (`TownLoading`), а перемотка тратит время на 625 ванильных чанков вокруг игрока; при 6 — +25%.
- Характер жителя (`Temperament.clock`, ±720 тиков) раньше никого не будит: им сдвигаются только сцены семьи, самая ранняя прогулка (школа) — после рассвета.
- В логе — `vnap monster: <вид> <тип спавна> at … light= sky= roofed= time … bell …` (монстры в радиусе города; почти все — `NATURAL` в пещерах под деревней и в тени елей днём) и `vnap siege: …` (ванильная осада).
- `restart.sh` ждёт клиента, пока процесс жив (до 20 минут), и повторяет вход в мир: проверка «клиент упал» ловила безобидное `GLFW icon error:` macOS, и клиент оставался в меню.

### Свежие деревни на серверах и аудит застреваний (20.10.2026)

- Прогон: 3 сервера × 2 свежие деревни × 3 суток с мобами (`server.py start N --fresh --at X 160 Z`, `/locate` через RCON, сценарий с `deaths` и `/vnap check` каждые сутки). Потерь 0, `check` 0. Нашлось: лавочник трое суток стоял на крыше рыночного навеса деревни мира, дом-лавка 226 из 226.
- **Открытый люк — преграда** (`mixin/WalkNodeEvaluatorMixin`): ванилла считает любой люк проходимым, и открытый (стоячая створка) тоже; клумба тайги, обнесённая открытыми люками, стояла на пути к укрытию — шестеро вошли, выйти не смогли, зомби убил всех за ночь. Над лестницей-стремянкой открытый люк — лаз, проходим. Тест `anOpenTrapdoorIsNoWayThrough`.
- **Лавочник появляется у колокола** — в центре деревни, где все собираются: земля в 1–4 блоках от колокола на его высоте или ниже (`Ground.near(…, bell.y, 0, 4)`), никогда выше — у колокола под рыночным навесом «землёй» была крыша навеса (`near` берёт верхний блок), и лавочник трое суток стоял на ней. Караван — так же от края, на высоте прилавка или ниже. Поиска пути и запасных вариантов нет.
- **Отказ от недостижимого**: `Hands` — ветка «далеко, иду к блоку» считает промахи (3 — `defer`), «далеко» — по горизонтали (шпиль над головой не далеко); `Wrecker` после 3 пустых походов к ближнему — `STUCK`, дом встаёт на день (`pausedDay`). Поручения (`ErrandRunner`): место, до которого житель не дошёл, — «недостижимо сегодня» (одна память на все поведения), то же поручение сразу FAILED; садовник выбирает растения мимо таких.
- Задания `Placements`, которые пропали без установки: перенос колокола (`bellMove`) и голем (`Network.golem`) больше не ждут их вечно. Кровати бездомным (`Shelter.beds`) — свободные кровати города против бездомных (`HomeProjects.freeBeds`), а не каждого по отдельности (кровать покупалась каждый день). Строитель, бросивший работу, сразу отпускает свой блок и роль «за материалами» (`job.release` в `stop`). Помощник берёт ближайший дом, который не на паузе и не полон (`forBuilder` с условием). Хозяин умер без наследника (супруг — по UUID, и выгруженный) — недостроенный дом закрывается (`Market.settle`, проект удаляется), не держит землю и деньги.
- Экономика: тележка и продажа переносят **настоящие стопки** (`Produce.take`), не копии первой (зачарованная книга размножалась); остаток стройки лавка берёт только под место на полке (`Produce.room`), казна больше не печатает монеты за сотни блоков сноса.
- Утечки: `Roads.features` чистятся, когда вещи нет и её не ждут; бюро находок — однотипное складывается, не больше `LOST_KEPT`=54 стопок; вещи сноса без места в доме — в бюро находок (а не вечно в `stash`); `vnap_slow_logged` не пишется в NBT; садовнику платят раз в день на жителя.
- Затычки сужены: неуязвимость к падению и удушью — только у строящего руками (`LifeBrain.building`), не у любого «занятого». Дом мира с планом роста не сносится, если рост сейчас нельзя (долг, место) — ждёт. Деревья в зелени — не ближе 4 к дороге. Отрезки дальнего пути (`AgendaBehavior.leg`) — точка на суше по `LandRandomPos`, а не прямо в холм.
- **Заявка лавки = нехватка, не сумма** (`Market.supply`, `orders.merge(…, Integer::max)`): строитель у пустого прилавка за день приходил раз пять, и каждый раз к заявке прибавлялось то же недостающее — утренняя поставка привозила в разы больше нужного (в пустыне +6400 товаров), касса и казна платили, казна допечатывала тысячи (`vnap mint: … Market.restock`). Тест `aBuilderBackAtASoldOutStallOrdersTheShortfallOnce`.
- **Укрытие не шлёт в ту же недостижимую комнату** (`Shelter.MISSED`): комната, до которой житель не дошёл, на сегодня для него вычёркивается (лавочника снежной деревни слали 12 раз за грозу, погиб снаружи).
- Чистка: `Brain.getRunningBehaviors`/`getMemories` (устаревшие отладочные) — через `mixin/BrainAccessor` и `LifeBrain.running`; обёртки `Chapel.lay/plot/footprint`, `Workshops.taken` удалены (вызовы — `TownPlots.*(…, Kind.CHAPEL)`, `Land.around`); перевод изножья в изголовье для сохранений до 18.10 убран. `/vnap day` — день деревни против часов мира.
- Не сделано: пустыня гибнет в первую ночь от монстров из тёмных крытых полостей под деревней (свет мода — только в комнатах и на открытой земле).
- Оставлено: `Hands.findSpot` смотрит высокую коробку (строят с земли), цена — после паузы промаха; бесконечные повторы улиц/дворов раз в 3–5 дней без счётчика.

## Мультиплеер (аудит 20.10.2026)

Мод один на обе стороны: серверного плагина нет и не нужно (как у Create, MineColonies, Farmer's Delight) — мод ставится и на сервер, и игрокам; JEI/EMI в `neoforge.mods.toml` — необязательные, `side = "CLIENT"`. Проверено живьём: выделенный сервер и два клиента одного аккаунта (offline-режим, `Dev` и `Dev2`), и LAN (хозяин + гость).

- **Код клиента** — только в `client/` и `@EventBusSubscriber(value = Dist.CLIENT)`; обработчики пакетов в `ClientPayloadHandlers` не трогают классы экранов напрямую (экраны — через `NoticeBoardClient` и т. п.) и берут игрока из `context.player()`, а не `Minecraft.getInstance()`. Выделенный сервер грузит мод — проверка `server.py start`.
- **Пакеты**: `ItemStack` — только `OPTIONAL_STREAM_CODEC` (пустой стак ронял кодек), анимации и боль — `sendToPlayersTrackingEntity`; полоса настроения — каждому игроку его ближайшей деревни (раз в 100 тиков, `VillageMoodApi.syncPlayers`); пороги настроения — `MoodRulesPayload` при входе.
- **Каждому игроку своё**: лимит продаж лавке (`Shops.Shop.paid(uuid)`; и доска объявлений — тот же лимит), задания (взять — только своего города), реакции на время суток и сложность — по ключу игрока; кто вышел — `PlayerLoggedOutEvent` чистит его наблюдения и паузу доски. Открытые окна одной лавки обновляются у всех после покупки (`ShopMenu.push`).
- **Наблюдатели** не в счёт: «рядом ли игрок», «видят ли» (`VillagerHome.unseen` — телепорты застрявших, питомцев, путников), толпа, реплики. Ванилла не даёт наблюдателю использовать блоки — доска/лавка в наблюдателе не открываются (не баг).
- **Защита от клиента**: доска не чаще раза в 10 тиков на игрока (`NoticeBoard.tooSoon`), флаг города — соседи, хозяева участков и op (`mayRaiseFlag`), `/vnap` по умолчанию только в dev (`debugCommands` = `!FMLEnvironment.production`), город держит чанки не больше `MAX_HELD_TOWNS`=8.
- **Настроение деревни — общее** для всех игроков (отношение деревни к игрокам вообще), не своё у каждого.
- Второй проход (20.10.2026): статические карты по жителю чистятся, когда он ушёл насовсем (`EntityLeaveLevelEvent` с `shouldDestroy` в `Family`: очередь дел, укрытие, «застрявшие», детская кровать, свадьба), а не только при остановке сервера; клиент, побывавший на чужом сервере, перечитывает пороги настроения перед своим миром (`ServerAboutToStartEvent` → `MoodConfig.load`); новые настройки от op уходят всем игрокам; задания `Placements` — только в верхнем мире (в них нет измерения).
- **Призрачная занятость кровати**: кровать с `occupied=true`, в которой никто не спит (спящего выгрузили или убили, сейв это сохранил), ванилла не чинит и каждую ночь стирает хозяину HOME — `keepHome` снимает флаг (тест `aBedMarkedSleptInWithNobodyInItIsFreed`; нашёлся в dev-мире у мэра и старика).
- Ключи по колоколу/месту — с измерением: обряды (`VillageScriptDirector.Key`), соседи (`Neighbours`, сохраняемый ключ `измерение@колокол`; старых ключей не читаем), музыка, прятки, детская, помощники стройки (`GlobalPos`). Дневной лимит пожертвований — в данных игрока (`vnap_gift_day`/`vnap_gift_copper`), перезапуск сервера его не сбрасывает. Обряд в тестах забывается через `VillageScriptDirector.forgetRunning`, без рефлексии.
- Проверка: `python3 tools/dev/server.py start 1 --fresh` → `tools/dev/restart.sh --server 127.0.0.1:25601` → `tools/dev/client2.sh 127.0.0.1:25601 Dev2`; второй клиентом управлять `VL_MCP=neoforge/versions/1.21.1/run-c2/mcp/server.json python3 tools/dev/mcp.py …`. LAN: в мире хозяина `/vnap offline`, `/publish false survival 25599`, затем `client2.sh 127.0.0.1:25599`.

Шпиль: наковальня Ядра, сундук слоя (`ThemedChestScreen`, своё меню `SpireBlocks.CHEST_MENU` = ванильный `ChestMenu`), скрижаль и летопись (пергамент в латунной раме). ## Озвучка (локальный TTS, MLX)

- venv: `.venv` (python 3.13, `tools/voice/requirements.txt`), модель — `DEFAULT_MODEL` в `tools/voice/dub.py`, нужен `ffmpeg`.
- `dub.py` берёт референс **своего языка и своего спикера**: speaker клипа берётся из группы в `dialogues.json`; есть `tools/voice/speaker/<lang>/<speaker>/ref.{wav,txt}` (`child`, `woman`, `parrot`, `infant`) — берётся он, иначе общий `tools/voice/speaker/<lang>/ref.{wav,txt}`. Фильтр `--speaker child` (повторяемый). Клон копирует акцент референса — EN нельзя делать с RU-референсом (так и случилась беда 17.10.2026).
- **Теги эмоций** (18.10.2026): Модель разыгрывает теги в квадратных скобках (`[gasp]`, `[sigh]`, `[snoring]`, `[whisper]`, свободная форма `[sad sigh]`, `[snoring, then a snort]`; тег перед словами, к которым относится). Теги пишутся **прямо в тексте реплики** EN и RU (lang/спеки): `"[gasp] Я открыл новые сделки!!"`. Скрипты текст не переписывают — `tts_text.for_tts` только ставит точку в конце; субтитры прячут теги (`DialogueSubtitleState`), `check.py` сверяет слова без тегов (`tts_text.plain`). Ремарки `*Gasp*`/`(кричит)` больше не писать — сразу тег. Реплика заканчивается словом, а не звукоподражанием: на хвосте «Zzz...», «Ммф», «Oooooh!» Fish рвёт конец, а Whisper его не слышит (`[snoring] Zzz... emeralds...`, не `...emeralds... zzz`); короткие возгласы-слова («Ow!», «Ах!», «Phew.») — можно.
- Невербальных реплик как отдельного вида больше нет: смех, крик, храп, блеяние — обычные реплики с тегом и звуковыми словами (`[screaming] А-а-а! Мама!`), озвучиваются как все. 18.10.2026 все 124 такие реплики переписаны (`apply_audit.py` rewrite: новые id, старые клипы удалены — RU-«невербальные» были побайтовыми копиями EN-оригиналов). Пробы — `tools/voice/out/emotion_test/`, `tools/voice/out/emotion_lines/`.
- Прогон `dub.py` в три этапа: (1) каждый нужный клип делается один раз, без проверок; (2) все сделанные проверяются (громкий хвост, длина, последнее слово через Whisper); (3) плохие переделываются другими сидами, «!» вместо «.», `<lang>_tts_short`, каждый вариант с проверкой. Сделанные, но не проверенные клипы записаны в `tools/voice/out/unchecked_<lang>.txt` — остановленный прогон проверит их при следующем запуске. Раз в клип в лог пишется прогноз: сколько осталось и когда закончит этап 1. Пока идёт, держит Mac бодрствующим (`caffeinate -w`).
- **Клипы — моно** (19.10.2026): Minecraft позиционирует звук и ослабляет его с расстоянием только у моно-источников, а встроенный кодер ffmpeg `vorbis` пишет лишь стерео — поэтому все 10 726 голосов были стерео (два одинаковых канала) и звучали одинаково отовсюду. `dub.py: to_ogg` пишет моно через libsndfile/libvorbis (`soundfile`, `--ogg-q` 0..10 → `compression_level`); готовые клипы перекодированы без TTS (каналы совпадали побайтово, длина до сэмпла та же, `compression_level`=0,1: файлы ×1,12, отличие от оригинала 29–39 дБ; время изменения сохранено — от него зависит переозвучка после смены `ref.wav`). Голоса — 528 МБ.
- Без `--force` генерируются только отсутствующие клипы; повторный запуск продолжает с места.
- Манифесты по умолчанию — все `tools/voice/manifests/*.json`, кроме `regen.json`. `scan.py --lang <l>` ищет обрезанные клипы и пишет `manifests/regen.json` → `dub.py --manifest tools/voice/manifests/regen.json --force`.
- `<id>.PENDING_TTS` в `sounds/voice/<lang>/` — текстовый маркер «клип ждёт TTS»; `dub.py` удаляет его, когда пишет ogg; в jar не попадает (`exclude` в `neoforge/build.gradle`). Сколько осталось: `ls …/voice/en/*.PENDING_TTS | wc -l`.
- Логи прогонов — `tools/voice/logs/` (в .gitignore), выход `scan.py` — `tools/voice/out/`.
- **Одна команда на язык озвучивает всё, что нужно** (запускает пользователь; новые клипы, переозвучка, расшифровка референсов, длительности EN):
  ```bash
  .venv/bin/python tools/voice/dub.py --lang ru
  .venv/bin/python tools/voice/dub.py --lang en
  ```
- **Обрезка слов (разобрано 18.10.2026)**: клип в игре звучит, пока не истечёт длительность его реплики в `dialogues.json`; длительность одна на EN и RU. Она устаревала (`gen_from_spec` пишет оценку по тексту, старый `duration_from_ogg.py` мерил только EN и только после полного EN-прогона), и 2515 из 3322 клипов обрезались. Теперь `duration_from_ogg.py` ставит каждой реплике длину самого длинного из её EN/RU-клипов (субтитры растягиваются); его зовут `dub.py` после любого прогона (и прерванного), `gen_from_spec.py`, а `check_lines.py` падает, если клип длиннее реплики (`--check`). Клиент (`DialogueSoundState`) больше не глушит клип по таймеру — только при смерти жителя или новой реплике. Сами файлы целые (огибающая всех клипов + Whisper на выборке).
- Модель обрывает очень короткие фразы с «.»/«...» на конце на любом сиде (`Привет.` — 7 токенов, громкий хвост); с «!» те же слова заканчиваются чисто — `dub.py` после неудачных сидов сам пробует «!».
  Клип делается, если его нет, если рядом лежит `<id>.PENDING_TTS` или если он старше `ref.wav` своего спикера (спикер получил свой голос: старые детские клипы, озвученные взрослым, переделываются сами). Голос берётся по `speaker` группы: `speaker/<lang>/<speaker>/` (`child`, `woman`, `parrot`, `infant`), иначе общий `speaker/<lang>/`. `ref.wav` без `ref.txt` сначала расшифровывается Whisper (текст печатается — проверить; RU-Whisper любит дописать «Продолжение следует…»). После любого прогона сам запускает `duration_from_ogg.py`. `--speaker`, `--only`, `--force` — для ручных случаев.
- Новый голос: положить `tools/voice/speaker/<lang>/<speaker>/ref.wav` (mono, 48 кГц: `ffmpeg -i in.mp3 -ac 1 -ar 48000 ref.wav`), `ref.txt` — точный текст или пусть расшифрует `dub.py`. Агент сам модели (TTS, Whisper) не запускает — только готовит файлы и пишет команды.

## Правила (не нарушать)

- Ответы пользователю — по-русски.
- **Никогда** `git commit --amend`. Коммиты/пуш — только по явной просьбе. При релизе: tag + `gh release create` (см. глобальные правила).
- Не редактировать файлы планов (`~/.cursor/plans/*`, `docs/plans/*`) — только читать.
- Не публиковать на Modrinth.
- Не генерировать TTS и не добавлять новые озвученные dialogue id без явной просьбы (команды — писать, запускать — пользователь).
- Не тащить в мод чужие голоса, модели, текстуры и код без лицензии.
- **Своё, а не ванильное** (22.10.2026, после жалобы пользователя на «дефолт»): у вещей мода — свои текстуры и эффекты; ванильная текстура/рендер (портал Незера, портал Энда, золотой блок как «сундук», морской фонарь как светильник) — только как временная заглушка с пометкой в «Не сделано». Перед сдачей визуальной работы — живые скриншоты в фоне (окно скрыто: `mcp.py mc.client.window '{"visible":false}'`), листы 3×3, разбор каждого кадра: нет ли «крапа» из случайных блоков, плавающих без опоры деталей, «палки» вместо силуэта.
- Не переименовывать репо.
- Оставить `-Werror`, NullAway, ErrorProne, SpotBugs. Не добавлять Checker Framework, InterMed, Fabric, Architectury.
- Комментарии в коде — только про ограничения, которые не видны из кода; стиль как у соседнего кода.
