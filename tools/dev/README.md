# Инструменты агента (dev-клиент, тесты, разбор)

Всё, чем агент проверяет мод без глаз на экране. Перечень обязателен к прочтению перед живой проверкой; кратко он же —
в `AGENTS.md` («Инструменты агента») и в навыке `.claude/skills/vl-dev/SKILL.md`. Новый инструмент — сюда же и туда же.

В одиночной игре `mc.server.command.run {"command","as"}` возвращает вывод команды (`mcc.py` берёт ответ из него, на выделенном сервере — из чата). `hand` — `main`/`offhand`. ## Выделенные серверы без окна (несколько деревень сразу)

Такт стоит одинаково в клиенте `--lite` и на сервере (20.10.2026, одна равнинная деревня, трое суток: клиент 1,89 мс/такт, сервер 2,06 мс/такт, ~2:45 на прогон) — рисование ни при чём. Выигрыш серверов: без экрана (не падают, когда гаснет монитор) и по деревне на сервер параллельно. 3 сервера = ~850 тактов/с вместе против ~485 у одного (×1,75; 10 ядер, рядом работал клиент другой сессии).

| Что | Как |
|---|---|
| Собрать мод и файлы запуска | `python3 tools/dev/server.py build` (gradle `classes`, `createServerLaunchScript`) |
| Поднять сервер N | (классы мода — своя копия в `run/servers/N/build`, ресурсы — жёсткие ссылки: чужая пересборка общей папки роняла серверы посреди прогона `NoClassDefFoundError`) `python3 tools/dev/server.py start N [--world "Имя"\|путь] [--fresh] [--at X Y Z]` — копия мира из `run/saves` (по умолчанию `New World`; `--fresh` — заново) в `run/servers/N/world`, порт 25600+N, RCON 25700+N, лог `/tmp/vl-server-N.log`; бот `Dev` у точки |
| **Прогон по сидам (главный для «полной проверки»)** | `python3 tools/dev/sweep.py [--seeds 1111,2222,3333] [--kinds plains,desert,savanna,taiga,snowy] [--per-seed 2] [--days 3] [--parallel 8] [--base 1] [--sleep]` — сам: мир на каждом сиде, `locate` деревень, по серверу на деревню (тот же сид, бот над колоколом), все параллельно, сценарий на N суток с мобами (`--sleep` — каждая ночь «проспана» `/time add`); сводка смерти/ловушки/`check`/лавка/допечатки/медленные такты/ошибки — в выводе и `/tmp/vl-sweep.md`, логи `/tmp/vl-sweep-N.log`, `/tmp/vl-server-N.log`. Номера серверов с `--base`: другая сессия может держать свои (проверить `pgrep -fl vl.server=`) |
| Новый мир по сиду | `python3 tools/dev/server.py start N --seed S` — мир генерируется с нуля (деревни, которых не касался ни один прогон); бот у точки появления, деревни — `locate` через `cmd`. Один сервер на деревню, все параллельно |
| Команды | `python3 tools/dev/server.py cmd N 'time set 1000' 'execute as Dev at Dev run vnap who 48'` (RCON, ответ печатается) |
| Сценарий | `python3 tools/dev/scenario.py --server N <сценарий>` — команды идут как `execute as Dev at Dev run …`, `sprint` и `deaths` читают лог сервера; по сценарию на сервер, серверы параллельно (в фоне) |
| Потери, проверка | `python3 tools/dev/deaths.py /tmp/vl-server-N.log`; `/vnap check` — шагом сценария |
| Остановить | `python3 tools/dev/server.py stop N` (`/vnap save`, `/stop`); `server.py status` |

- Бот: `/vnap bot <имя> <x y z>` / `/vnap bot <имя> remove` — игрок без клиента в списке игроков (как фейковые игроки Carpet): держит город (`TownLoading`), спавнит мобов и осады. Творческий, ничего ему не шлётся; раз в секунду опускается на землю, как творческий игрок без полёта (наблюдатель висит). Чанки двигает сам (клиента, который подтвердил бы телепорт, нет). Точку бота проверять (`data get entity Dev Pos`, `/vnap spot`): над пещерой он проваливается в неё — в пустыне 90512 130 93248 сидел в нише холма на y64, жители тянулись к нему, а монстры не спавнились в 24 блоках от него (замеры того места до 20.10.2026 мерили это); там ставить 90500 75 93246.
- В dev-мире `doMobSpawning false` — для живого прогона `/gamerule doMobSpawning true` в сценарии.
- Копировать мир, в котором сейчас клиент, нельзя (регионы пишутся) — копировать тот, где клиента нет, или после `restart.sh --stop`.
- `restart.sh` на сервере (`--server`) не ждёт сохранения мира: мир — сервера (клиент раньше не перезапускался вовсе).
- `restart.sh` убивает только клиент (`clientRunProgramArgs`); раньше `pkill fml.modFolders` убивал бы и серверы.

## Мультиплеер: сервер и два клиента

| Что | Как |
|---|---|
| Клиент на сервер | `tools/dev/restart.sh --server 127.0.0.1:2560N` — вход с титульного экрана (`mc.client.connection.connect`) |
| Второй клиент | `tools/dev/client2.sh ADDR [Имя]` (по умолчанию `Dev2`): своя папка `run-c2` (моды, конфиг, options дев-клиента), свой порт MCP, лог `/tmp/vl-client2.log`; управлять — `VL_MCP=neoforge/versions/1.21.1/run-c2/mcp/server.json python3 tools/dev/mcp.py …` (и `mcc.py`); закрыть — `client2.sh --stop [Имя]`. Один аккаунт — только offline-серверы |
| LAN | в мире хозяина `/vnap offline` (встроенный сервер перестаёт спрашивать аккаунт), `/publish false survival 25599`, затем `client2.sh 127.0.0.1:25599` |
| Моды сервера | `server.py` кладёт на сервер моды из `run/mods`, кроме MCP (Patchouli нужен с обеих сторон, иначе «Incompatible client») |

- `restart.sh` закрывает только клиент без `--username`, второй клиент живёт.
- Наблюдатель не использует блоки (ванилла): доску и лавку проверять в творческом/выживании.

## Бот-игрок внутри мода (`client/dev/DevBot`, 23.10.2026)

Внутренний инструмент отладки: бот управляет настоящим игроком dev-клиента каждый тик — клавиши ходьбы и прыжка, поворот головы, удар по готовности атаки, клик по блоку — и видит только то, что видит игрок (клиентский мир, сущности, надпись этажа). Путь ищет сам по блокам клиента (`DevBot.find`: шаг ±1, спуск до 3, лестницы, вода), поэтому непроходимое место показывает как есть. Команда только в dev-сборке (`Mc.production()` — нет команды). Задачи подключаются к ядру (`DevBot.Task`); сейчас одна:

- `/vnapbot climb <с> <по> [заточка] [секунд на этаж]` — Шпиль этаж за этажом (`ClimbTask`): скрижаль, стражи (ближайший; части босса тоже), сундук этажа (ближайший к порталу; тайник за треснувшей стеной не трогает), портал «дальше». Снаряжение главы на +заточку ставится командой на каждом этаже; не прошёл за время — пишет, кто остался и где, и идёт со следующего. Застрял на 15 с — пишет где и почему (расстояние, видимость стража) и телепортируется к цели. `/vnapbot stop`.
- Бой: одна цель, пока жива (на того, кто уже на расстоянии удара, отвлекается); бег на прямых участках пути; при здоровье < 7 пятится лицом к цели до 15; уходит из меток хранителя (сервер шлёт их боту пакетом `KeeperMarksPayload`, только при `debugCommands`).
- `/vnapbot tour` — обход ближайшего города (`TourTask`): места даёт сервер (`/vnap town tour`: колокол, доска, прилавок, двери, кладбище — строки `vnaptour …`, бот читает их из чата), идёт к каждому, открывает доску и лавку, пишет `at <вид> x y z` и `NO WAY to …`. Снимки — наблюдатель в scratchpad (`town_watch.py`: кадр на каждую `at`, через сутки обход снова).
- Два клиента сразу (башня и деревня, общая скорость `/tick rate`): `server.py start 1 --fresh --no-bot` (мир «New World» копией, без подставного игрока Dev, Dev и Dev2 — операторы), `restart.sh --server 127.0.0.1:25601`, `client2.sh 127.0.0.1:25601 Dev2`; окна скрывать `mcp.py mc.client.window '{"visible":false}'` (второму — `VL_MCP=…/run-c2/mcp/server.json`). Сетевая игра с хоста — только `/publish true …` (иначе у гостя нет команд). Скрипты сами подставляют текущую Java, если Homebrew обновил ту, что записана в launch-файлах.
- Запуск через MCP: `python3 tools/dev/mcp.py mc.client.command.run '{"command":"vnapbot climb 1 100 5 480"}'` (игрок — в верхнем мире у ворот шпиля, оттуда бот и входит). Лог — `neoforge/versions/1.21.1/run/devbot.log`. Снимки по этажам — скрипт-наблюдатель в scratchpad (`watch.py`: кадр раз в 6 с через MCP, лист на этаж).

## Смотреть без скриншотов (команды `/vnap`, op 2, `debugCommands`)

- `/vnap spot` — клетка под игроком: блок, свет блока и неба, крыша, поверхность; комната вокруг (закрыта или где открыта), тёмные клетки.
- `/vnap layer [dy] [r]` — карта слоя: `#` твёрдое, `D` дверь, `B` кровать, `T` люк, `F` забор/стена/калитка, `S` ступень/плита, `W` вода, `L` свет, `G` стекло, `C` контейнер, `~` растения, `.` воздух; `v` житель, `g` голем, `z` монстр, `@` игрок.
- `/vnap mobs [r]` — кто рядом (поверхность/под землёй) по видам.
- Стройка домов: `/vnap site` — ближайшая стройка (что дальше, деньги и фонд работ, склад, хозяин — где он и чем занят, находит ли он место у следующего блока, кто вокруг строит); `/vnap houses` — все проекты (у вставших — оставшиеся клетки и что в них); `/vnap worldhouses [r]` — дома сгенерированной деревни вокруг (шаблон, есть ли у него уровни, кто живёт, `*` — глава, какая стройка на нём); `/vnap family room [hand]` у главы — следующий уровень сразу или руками строителей; `/vnap worldhouse <шаблон|all> [l1|l2|l3] [cut]` — на расчищенной площадке у игрока ванильный дом и его уровень в 14 блоках восточнее (подвал в земле, `cut` срезает южную половину — видно комнаты, марш, подвал; `all` — все 34 сеткой 6 в ряд через 30). `/vnap home <имя>` пишет и дом мира, в котором кровать.
- `/vnap path <имя> [x y z]` — есть ли у жителя путь пешком к кровати (или к точке) и где он обрывается.
- `/vnap who [r]`, `/vnap home [имя]`, `/vnap check [r]`, `/vnap houses`, `/vnap town`, `/vnap mayor info`, `/vnap shop info|wants`, `/vnap family info`, `/vnap placements`, `/vnap roads [lots|…]` — состояние жителей, домов, города (подробно — `AGENTS.md`).
- Все ветки команды: `/help vnap`.

## Лог клиента `/tmp/vl-client.log`

- Не обрезать (`| tail`/`| head` по полному логу нельзя) — искать `rg`.
- Потери: строки `vnap death:` (кто, чем, убийца с местом, светом и крышей, время, дом/бездомный, в доме ли, спал ли, активность, кровать), `vnap gone:` (обращён, ушёл на хутор), `vnap shelter:` (куда отправлен на ночь).

## Что держит такт, профили, исходники игры

- `/tick sprint N` в конце пишет «N тактов в секунду (M мс за такт)» — бесплатный замер каждого прогона.
- `/neoforge tps` — такт по измерениям; `/neoforge track start entity|blockentity <секунды>`, потом `/neoforge track entity|blockentity` — 10 самых дорогих сущностей/блок-сущностей с типом и координатами (первый вопрос при лагах); `/neoforge entity list [фильтр]` — сколько чего (по чанкам при фильтре на один вид). В одиночной игре `track` раньше ронял клиент (общий `TimeTracker` клиента и встроенного сервера); `mixin/TimeTrackerMixin` меряет только поток сервера.
- `/perf start` … `/perf stop` — 10-секундный профиль сервера текстом (zip в `neoforge/versions/1.21.1/run/debug/profiling/`, распаковать и `rg`); `/jfr start` … `/jfr stop` — запись Flight Recorder с JSON-сводкой в `run/debug/` (`jfr summary|print --json <файл>`). Без игры: `jcmd <pid> Thread.print` / `jstack <pid>` (pid процесса с `fml.modFolders`), `jcmd <pid> JFR.start duration=60s filename=/tmp/vl.jfr`.
- Миксины: `JAVA_TOOL_OPTIONS='-Dmixin.debug.export=true -Dmixin.dumpTargetOnFailure=true' tools/dev/restart.sh` — преобразованные классы в `run/.mixin.out/` (что на самом деле вставилось).
- Исходники Minecraft и NeoForge (имена Mojang): `tools/dev/mcsrc.sh <Класс>` (весь файл), `-l <начало имени>` (пути), `-g '<regex>'` (кто вызывает/объявляет). Распаковывает jar сборки один раз в `/tmp/vl-mcsrc`.
- Не взято (20.10.2026): Spark (внешний мод, профиль бинарный; `/neoforge track` и `/perf` отвечают на тот же вопрос текстом), отладочные рендеры мозга/POI (в 1.21.1 для NeoForge их нет, а `/vnap who` текстом полезнее), JUnit testframework NeoForge (пробовали: экономит секунды, полный прогон держат запуск сервера и долгие GameTests — гонять `gts.sh <фильтр>`).

## Тесты и сборка

- `tools/dev/gts.sh` — все GameTests за ~45 с: gradle собирает и пишет скрипт запуска, `tools/dev/gts_shards.py` запускает `VL_SHARDS` (4) тестовых серверов сразу (у каждого своя папка мира `run-gts/<n>`, свой `-Dvl.tests`), партии раздаются по тому, сколько стоили в прошлый раз (`vnap test:`), большая `defaultBatch` делится по тестам; логи `/tmp/vl-gts-<n>.log`, все вместе — `/tmp/vl-gts.log`. 6 серверов медленнее (10 ядер, у каждого JVM свои потоки), 3 — так же. `tools/dev/gts.sh <классы,батчи,тесты>` — только эти, одним сервером через gradle (~25–40 с).
- Правила, без которых тесты нестабильны (20.10.2026): тест, который держит время суток (`onEachTick(setDayTime…)`) или долго живёт на нём, — в партии `life_day`/`life_night`, не в общей (в одной партии «ночной» и «дневной» тесты переводили часы каждый такт); перед каждой партией утро и ясно (`GameTestRunnerMixin`); не ждать фиксированное число тактов там, где можно ждать условие — свет (`LightWait.after`: задачи движка света по чанкам), тикающий чанк, жителя на земле (`succeedWhen`/опрос каждый такт).
- В конце `gts.sh` печатает, что держало прогон (`tools/dev/slow_tests.py [лог] [N]` по строкам `vnap test:` — их пишет `GameTestServerMixin`): партии по самому долгому тесту (тесты партии идут вместе, следующая ждёт), самые долгие тесты и самые тяжёлые запуски теста («own» — сколько тест считал сам на нулевом такте, пока вся партия ждала). 20.10.2026 так нашлось: A* дорог на каждой клетке искал кабинет мэра и пересчитывал радиус (`Towns.ours`) — партия `roads` 83 → 22 с, весь прогон 3:49 → 2:44; в горячих циклах — `Towns.territory(level, bell)` один раз.
- `./gradlew --no-configuration-cache --offline build` — с ErrorProne, NullAway, SpotBugs (отчёт `neoforge/versions/1.21.1/build/reports/spotbugs/main.html`).
- gradle и клиент не вместе (кроме `compileJava`).

## Порядок живой проверки

1. `restart.sh` → убедиться, что клиент в мире.
2. Наблюдателем осмотреться (`/vnap spot|layer|mobs`, скриншот при сомнении); прокручивать — творческим игроком над колоколом (наблюдатель город не держит: такт ~1,4 мс — ничего не тикало).
3. Сценарий в фоне → `deaths` и `/vnap check` в нём → `deaths.py`.
4. Нашлась проблема — `DevChecks` (`/vnap check`) или тест + строка в сценарий.

## Подводные камни

- Экран Mac погас — клиент не стартует («Failed to locate a primary monitor»); `restart.sh` об этом скажет.
- `pkill` клиента без `/vnap save` теряет регионы — только `restart.sh`.
- `mc.client.block.interact` работает только вплотную (≤ 4–5 блоков).
- Одновременно с другой сессией в том же клиенте не работать: проверить `pgrep -fl "scenario.py|clientRunProgramArgs"`; серверы — `server.py status`.
